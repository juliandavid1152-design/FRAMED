# Guía de Contribución

## 1. Introducción

El presente documento establece las directrices para la participación de los integrantes del proyecto FRAMED durante el desarrollo, mantenimiento y evolución del sistema. Su propósito es promover un trabajo colaborativo, organizado y consistente, garantizando que las contribuciones realizadas mantengan la calidad del proyecto y faciliten su administración mediante control de versiones.

---

# 2. Objetivo

Definir las buenas prácticas para la incorporación de cambios al repositorio del proyecto, asegurando la trazabilidad, la calidad del código y la adecuada documentación de cada modificación realizada.

---

# 3. Alcance

Esta guía aplica a todos los integrantes del proyecto que participen en actividades de:

- Desarrollo de funcionalidades.
- Modificación de la base de datos.
- Actualización de la documentación.
- Corrección de errores.
- Mejoras del sistema.
- Administración del repositorio GitHub.

---

# 4. Flujo de Trabajo

Las contribuciones deberán seguir el siguiente proceso:

1. Identificar la actividad o mejora a desarrollar.
2. Realizar los cambios correspondientes.
3. Verificar el correcto funcionamiento de la modificación.
4. Documentar los cambios cuando sea necesario.
5. Registrar un commit descriptivo.
6. Publicar los cambios en el repositorio.

---

# 5. Convención de Commits

Se recomienda utilizar mensajes claros y descriptivos que permitan identificar fácilmente la finalidad de cada modificación.

Ejemplos:

- Agrega script de creación de tablas principales.
- Implementa restricciones y llaves foráneas.
- Completa catálogos iniciales del sistema.
- Fortalece la documentación de arquitectura.
- Documenta manual técnico del proyecto.
- Corrige validaciones del módulo de establecimientos.

---

# 6. Buenas Prácticas

Durante el desarrollo del proyecto se recomienda:

- Mantener una estructura organizada del repositorio.
- Utilizar nombres descriptivos para archivos y objetos de base de datos.
- Evitar duplicidad de información.
- Documentar las funcionalidades implementadas.
- Mantener consistencia en el formato del código y de la documentación.
- Verificar el funcionamiento antes de publicar cambios.

---

# 7. Organización del Repositorio

El proyecto se organiza en los siguientes componentes principales:

- docs/
- sql/
- README.md
- CHANGELOG.md
- LICENSE
- .gitignore

Cada carpeta contiene la documentación y los recursos asociados a un componente específico del sistema.

---

# 8. Control de Versiones

El proyecto utiliza Git y GitHub para gestionar el historial de cambios.

Cada modificación realizada queda registrada mediante commits, permitiendo:

- Mantener la trazabilidad del desarrollo.
- Recuperar versiones anteriores.
- Facilitar el trabajo colaborativo.
- Controlar la evolución del proyecto.

---

# 9. Revisión de Cambios

Antes de incorporar una modificación al repositorio se recomienda verificar:

- Correcto funcionamiento.
- Ausencia de errores.
- Consistencia con la documentación existente.
- Cumplimiento de las convenciones establecidas.

---

# 10. Conclusiones

La aplicación de estas directrices favorece un desarrollo organizado y facilita el mantenimiento del proyecto FRAMED, promoviendo la calidad del código, la consistencia de la documentación y el adecuado control de versiones durante todo el ciclo de vida del sistema.
